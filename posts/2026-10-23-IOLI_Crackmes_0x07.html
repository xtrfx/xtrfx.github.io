Challenged level increased! Running file on the binary immediately shows that the 0x07 binary has been stripped. Strings search shows the same output as 0x06 with the LOLO string in place so probably a very similar logic. We sill have a main function but down below we can see that we have lost the convenient function names.

Based the previous analysis of 0x06 it is safe to assume that this is the 'check' function so I went ahead and renamed it just for easier tracking. Likewise, I updated all the other function names. There are a couple of smaller functions, which I left alone, which did not seem to alter the execution logic.

Thus, the logic seems to be the same, parell is called when pin integer sum is 0x10. Environment is checked for a flag LOL with an arbitrary value and the last pin digit is again an even number and indeed that is the case.

Interestingly, the decompile of parell has a slight change, where we now have two ifs and reference to an address at 0x404064.

In static analysis the address shows up with a value 0, meaning the second if conditional should fail, yet as we saw above through no effort of our own, it does not. What gives? If we trace calls to that address we see that both parell and dummy call it. We can see that if dummy executes, a one is moved to that address, which we can confirm with a dynamic debug of r2.

So a slightly obfuscation of the execution logic, which would presumably mean wasted time in analysis of a binary with no prior knowledge of its structure and function. Lessons learned. On to the next one.
