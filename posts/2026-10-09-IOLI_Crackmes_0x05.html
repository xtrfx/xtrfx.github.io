Similar to the 0x04 crackme, 0x05 uses the previous pin check function for a static value comparison (instruction at 0x40129d) to reference value 0x10 (decimal 16) . This time the integers must add up to 16 but also we have a call to an additional function to parell at 0x4012aa. What does it do?

|     │ ╎   0x0040129a      0145fc         add dword [var_4h], eax
│     │ ╎   0x0040129d      837dfc10       cmp dword [var_4h], 0x10
│     │┌──< 0x004012a1      750c           jne 0x4012af
│     ││╎   0x004012a3      488b45d8       mov rax, qword [s]
│     ││╎   0x004012a7      4889c7         mov rdi, rax                ; char *arg1
│     ││╎   0x004012aa      e827ffffff     call sym.parell

Decompiling the check function, we can see that parell is called only if a pin with a sum of 16 given. Decompiling with pdd we get the following:

#include <stdint.h>
int64_t parell (char * arg1) {
    char * s;
    int64_t var_4h;
    rdi = arg1;
    s = rdi;
    rdx = &var_4h;
    rax = s;
    rsi = 0x00402004;
    rdi = rax;
    eax = 0;
    isoc99_sscanf ();
    eax = var_4h;
    eax &= 1; // This is bitwise AND the value in EAX

    if (eax == 0) {
    // this check is looking if the number is Even (LSB is 0)
        puts ("Password OK!");
        exit (0);
    }
    return rax;
}
[0x004010f0]>

Looking at the Password OK conditional we can see that we are checking for even or odd numbers[1]. (instruction at 0x41Success is only if the last number of the entered pin is even and the total adds up to 16, for example:

> ./crackme0x05
IOLI Crackme Level 0x05
Password: 556
Password OK!

> ./crackme0x05
IOLI Crackme Level 0x05
Password: 5533
Password Incorrect!

I wanted to be clear on the assembly that carries out this operation as the test instruction in 0x401208 was not apparent for me so I asked Claude for a bit of clarity:

---snip----
│           0x00401202      8b45fc         mov eax, dword [var_4h]
│           0x00401205      83e001         and eax, 1
│           0x00401208      85c0           test eax, eax

Here are the key points of the reply:

The TEST instruction: 1. Performs a bitwise AND between the two operands 2. Updates the zero flag (ZF), sign flag (SF), and parity flag (PF) based on the result

because any number AND'd with itself equals itself:

eax AND eax = eax

After the previous line and eax, 1, eax now contains either 0 or 1:

  • If the original number was odd: `eax = 1' //ZF is 0
  • If the original number was even: `eax = 0' //ZF is 1
