Securing old thumb-drives

***Disclaimer: For truly sensitive data, please consider doing your own homework on top of this basic cleaning process (mind your actual threat model and that sort of thing). Also, be careful and don't erase drives you actually care about. (work in a VM if you can)

Over the years we have collected a large number of thumb drives (gifts, conference promo items, corporate branding and such.) I don't really know what is on each drive but given their typical use cases (data for printing/data transfer) I can imagine some sensitive data residing on them, probably quite a lot actually. As part of an overall effort to minimise our data risks, I have decided to clean up these things, in a secure manner.

Handling 'Data-at-rest' as it turns out demands some consideration: 1) future copies of this data should be stored securely 2) the security has to work across several platforms 3) older/smaller drives will be slated for destruction without data exposure 4) there are 20+ usb drives that need backups, data wipes and possible formatting - lot's of opportunities to make mistakes

Data Security

Independent of drive destiny, a bit of bit-bleaching is in order and the devices should be wiped with either zeros or random numbers. Devices that will store data in the future will be bleached with random numbers to make it appear that everything on the drive is just random data.

Cross platform options

Once wiped, the user has options: 1) LUKS with cryptsetup - for linux use only or 2) VeraCrypt for cross-platform and 3) Bitlocker for windows only. Bitlocker being a windows only protocol, is beyond the scope of these scripts after a device has been wiped.

Destruction

Drives destined for destruction are wiped with zeros just as precaution, prior to the low-tech hammer smash. For me this is overkill, but perhaps not for others.

Automation

To control, automate and guardrail the process, a series of shell scripts seems to be in order. The scripts allow for offering options, organising the process/making it repeatable and providing warnings along the way to help make sure that no functional drive gets wiped.

As an additional measure, I suggest doing this in a VM, that way you only risk wiping the VM instead of a critical system drive. Scripts on github

Additional considerations:

For truly sensitive data, the scripts might not provide the requisite level of 'security.' For instance, LUKS encryption in its basic form leaves a plain text header on the drive openly announcing the device is encrypted.

Referring back to the original disclaimer, if you ever use these, consider header-less LUKS, hidden drives or VeraCrypt options as well as maybe a data-nuke password should you ever be forced to 'show your data.'
